## 2. The CI/CD Pipeline

Every push to `main` or `dev`, and every PR targeting those branches, triggers the pipeline.

```
Stage 1: validate-frontmatter   →  astro check (Zod schema)
Stage 2: check-slugs            →  scripts/check-slugs.mjs (no duplicate slugs)
Stage 3: check-links            →  scripts/check-links.mjs (no broken /suhba/* refs)
Stage 4: build                  →  astro build + pagefind postbuild
Stage 5: lighthouse             →  LCP < 1.5s, CLS < 0.05, Perf ≥ 95, A11y ≥ 90
Stage 6: deploy (main only)     →  cloudflare/wrangler-action@v3
```

**Deploying:** Merging a PR into `main` automatically deploys to `suhbalibrary.org`. No manual deploy steps.

**Re-running a failed stage:** Go to the failed GitHub Actions run → click "Re-run failed jobs" to re-run only the failed stage(s).

## 3. How to Add a Discourse (Content Workflow)

This is the primary ongoing maintenance task. Every new discourse follows this process:

### Step 1 — Create a branch

```bash
git checkout dev
git pull
git checkout -b content/YYYY-MM-DD-short-title
```

### Step 2 — Create the Markdown file

Create `src/content/discourses/YYYY-MM-DD-short-title.md` using this template:

```yaml
---
title: "Full Title of the Discourse"
date: YYYY-MM-DD
date_hijri: "D Month YYYY"       # Optional — computed automatically if absent
speaker:
  - "Speaker Full Name"
location_country: "Country"
location_city: "City"             # Optional
location_venue: "Venue Name"      # Optional
language: "en"                    # BCP 47: en, ar, tr, ur, etc.
slug: "YYYY-MM-DD-short-title"    # IMMUTABLE — never change after publish
status: "published"               # published | draft | archived
topic:
  - "Topic One"
  - "Topic Two"
transcript_quality: "draft"       # draft | reviewed | verified
version: 1
youtube_url: "https://www.youtube.com/watch?v=..."   # Optional
image: "https://r2.suhbalibrary.org/filename.jpg"    # Optional
quotes_verified:                  # Optional — curated quotes for WotD
  - "Quote text here."
edited_at:
---

Discourse body text in Markdown here...
```

**Slug rules:**
- Format: `YYYY-MM-DD-short-title` — lowercase letters, digits, hyphens only
- **Immutable once published** — never rename a slug after it has been published
- Must be unique across all discourses (CI Stage 2 enforces this)

**Content cross-references:**
- Internal links to other discourses must use `/suhba/exact-slug` format
- CI Stage 3 verifies all referenced slugs exist as published discourses

### Step 3 — Open a PR

```bash
git add src/content/discourses/YYYY-MM-DD-short-title.md
git commit -m "Add discourse: Full Title of the Discourse"
git push -u origin content/YYYY-MM-DD-short-title
```

Open a PR from your branch targeting `dev`. CI runs automatically. When CI passes and the PR is merged to `dev`, you can then open a PR from `dev` to `main` to deploy.

### Step 4 — Upload media to R2 (if applicable)

Images for discourses go in the Cloudflare R2 bucket `suhba-media`.
- Upload via Cloudflare Dashboard → R2 → `suhba-media` → Upload
- Public URL format: `https://r2.suhbalibrary.org/filename.jpg`
- Reference from frontmatter: `image: "https://r2.suhbalibrary.org/filename.jpg"`
- Default OG image (used when no image is specified): `og-default.jpg` already in the bucket

## 4. How to Add a Speaker Biography

Speaker bios live in `src/data/speakers/`. The filename must match the slug format of the speaker's name (lowercase, hyphens, no special characters).

To find the correct filename for a speaker: the slug is generated as:
```js
name.toLowerCase().replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '')
```

Example: `"Shaykh Nazim al-Haqqani"` → `shaykh-nazim-al-haqqani.md`

Template:
```markdown
---
name: "Speaker Full Name"
born: 1922
died: 2014       # Optional — omit if still living
birth_place: "City, Country"
---

Biographical text in Markdown paragraphs here.

Multiple paragraphs are supported.
```

The bio is rendered on the speaker's page at `/speakers/[slug]`. If no bio file exists, the page shows a friendly fallback message.

**Note:** Full Markdown rendering in bio bodies is currently paragraph-split only (not full Markdown). Full Markdown rendering (headings, lists, links) is a pending task — see Workstream D.

## 5. Development Workflow

### Prerequisites

- Node.js ≥ 22.0.0
- pnpm ≥ 9.0.0 (`npm install -g pnpm`)

### Local setup

```bash
git clone https://github.com/project-ghuraba/suhba-library.git
cd suhba-library
pnpm install
pnpm dev        # Dev server at http://localhost:4321
```

### Building and testing locally

```bash
pnpm build      # Full build + pagefind postbuild
pnpm preview    # Serve dist/ locally
```

**Note:** Pagefind search is unavailable in dev mode (`pnpm dev`). Run `pnpm build && pnpm preview` to test search locally.

### Running CI checks locally

```bash
pnpm run validate      # Stage 1: type check + schema validation
pnpm run lint:slugs    # Stage 2: duplicate slug detection
pnpm run lint:links    # Stage 3: broken link detection
```

## 6. Architecture Summary

| Concern | How it works |
|---|---|
| **Content source** | Markdown files in `src/content/discourses/` — all metadata in YAML frontmatter |
| **Schema enforcement** | Zod schema in `src/content/config.ts` — `astro check` fails the build on any violation |
| **Static pages** | Astro 5 with `output: 'static'` — every route pre-rendered at build time |
| **Styling** | Tailwind CSS v4 — all tokens in `src/styles/global.css` under `@theme {}` |
| **Full-text search** | Pagefind — post-build static index in `dist/pagefind/` |
| **Faceted filtering** | `/search-index.json` — read by client-side JS on the `/search` page |
| **Hijri dates** | `hijri-converter` — computed at build time; shown with `(est.)` when not manually provided |
| **Dark mode** | System preference default; toggle stored in `localStorage` key `suhba-theme` |
| **Reading size** | Font size toggle stored in `localStorage` key `suhba-reading-size` |
| **Analytics** | Cloudflare Web Analytics — automatic beacon injection at the CDN edge, no code required |
| **Media** | Cloudflare R2 bucket `suhba-media`; public at `r2.suhbalibrary.org` |

### 8.1 Workstream D — Speaker Pages (immediate priority)

**What's left:**

#### D1 — Full Markdown rendering in bio bodies
Currently, speaker bios are split on double-newlines and wrapped in `<p>` tags. Full Markdown (headings, bold, links, lists) is not rendered.

**File to edit:** `src/pages/speakers/[speaker].astro` — lines 46–55

**Current code:**
```ts
bioHtml = body
  .split(/\n{2,}/)
  .map(p => `<p>${p.trim()}</p>`)
  .join('\n');
```

**Fix:** Use Astro's `<Content />` with a content collection, or use a Markdown parsing library at build time. The simplest approach for Astro 5 is to create a `speakers` content collection in `src/content/config.ts` using a glob loader on `src/data/speakers/*.md`, then use `render(entry)` to get a `<Content />` component — exactly how discourse pages work.

Steps:
1. In `src/content/config.ts`, add a `speakers` collection:
   ```ts
   speakers: defineCollection({
     loader: glob({ pattern: '**/*.md', base: './src/data/speakers' }),
     schema: z.object({
       name: z.string(),
       born: z.number().optional(),
       died: z.number().optional(),
       birth_place: z.string().optional(),
     }),
   }),
   ```
2. In `speakers/[speaker].astro`:
   - Import `getCollection` from `astro:content` (already imported)
   - Load the matching speaker entry from the `speakers` collection
   - Use `render(speakerEntry)` to get `<SpeakerContent />`
   - Replace `<div set:html={bioHtml}>` with `<SpeakerContent />`
3. Remove the manual `readFile` / `bioHtml` logic entirely

#### D2 — Speaker portrait images
Each speaker page shows a large initials avatar (e.g. "NA" for Nazim al-Haqqani). The PRD specifies a real portrait image.

Steps:
1. Upload portrait images to R2 bucket `suhba-media` (e.g. `shaykh-nazim-al-haqqani.jpg`)
2. Add an `image` field to the speaker schema in `config.ts`
3. Add image frontmatter to each `src/data/speakers/*.md` file
4. Update `speakers/[speaker].astro` to render `<img>` instead of the initials avatar

### 8.2 Workstream E — Analytics Events

The Cloudflare Web Analytics beacon is live (auto-injected at edge). Custom events need to be wired to the `data-cf-event` attributes that already exist on several elements.

**Priority events to implement:**

#### E1 — Quote copy event
In `src/pages/index.astro`, the copy button for Wisdom of the Day needs a `data-cf-event="quote_copy"` attribute and the CF Analytics `window.cf_analytics` call. See [Cloudflare Web Analytics custom events docs](https://developers.cloudflare.com/analytics/web-analytics/tracking-custom-events/).

#### E2 — Share button clicks
In `src/pages/suhba/[slug].astro`, each share button (`.share-icon`) needs to fire an analytics event. The YouTube button already has `data-cf-event="youtube_click"`.

The pattern for all custom events:
```js
if (window.cf_analytics) {
  window.cf_analytics.pushEvent('event_name', { slug: 'discourse-slug' });
}
```

Add this to the existing `<script>` blocks in each page.

#### E3 — Search query logging
In `src/pages/search.astro`, the filter panel JS can fire an event when a search/filter is applied:
```js
if (window.cf_analytics) {
  window.cf_analytics.pushEvent('filter_applied', { type: 'speaker', value: speakerValue });
}
```

### 8.3 Workstream C — Pagefind Synonyms (deferred v1 item)

The synonyms file `src/config/synonyms.json` contains 15 synonym groups (e.g. `Shaykh` / `Sheikh`, `Dhikr` / `Zikr`). These are not yet ingested by Pagefind because Pagefind 1.x CLI has no native synonym support.

**To implement:** Switch from Pagefind CLI to the Pagefind Node.js indexing API. This means replacing the `pnpm run pagefind` script with a custom Node.js script that:
1. Creates a `PagefindIndex` programmatically
2. Feeds synonym definitions from `synonyms.json`
3. Indexes all files in `dist/`
4. Writes the index to `dist/pagefind/`

Reference: [Pagefind Node.js indexing API](https://pagefind.app/docs/node-api/)

The `pagefind` package is already installed. The Node script would be added to `scripts/build-search-index.mjs`, and the `postbuild` script in `package.json` would be updated to call it.

### 8.5 Content Pipeline — Ongoing

The primary ongoing work is adding real discourses. There are currently 5 sample discourses. The goal is to build a meaningful archive.

**Recommended batch approach:**
1. Prepare 10–20 discourses in a `content/batch-001` branch
2. Run `pnpm run validate && pnpm run lint:slugs && pnpm run lint:links` locally before pushing
3. Open a PR to `dev` — CI validates the batch
4. Merge to `dev`, then PR from `dev` to `main` to deploy

**Transcript quality levels:**
- `draft` — raw transcript, may have errors
- `reviewed` — human-reviewed for accuracy
- `verified` — reviewed + quotes confirmed against audio/video

**When to promote a transcript quality:**
Update the `transcript_quality` frontmatter field. Increment `version` and set `edited_at` to the date of the change.
